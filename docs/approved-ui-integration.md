# Approved Outpost UI integration

27 October 2026. Local implementation for review; no deployment.

## What changed

The active `public/` frontend uses the approved Godot-derived HTML components from the marketing repository's `brand/outpost-ui-components` library. The cinematic hero, game/studio logos, page content, concept-art labels, current release/store state, routes and form payload names are retained.

- Bronze and burgundy velvet shared navigation, approved action buttons and the parchment language picker.
- Cinzel display typography and the approved Noto body/regional fonts.
- Parchment feature panels, fixed-scale media frames, gallery selection halos and newsletter form.
- Matching Press, Support, Contact and Privacy reading/form surfaces, FAQ disclosures, footer and 404 actions.
- Native form controls with approved fields, checkboxes, dropdowns, textarea scrolling, and pending/success/error statuses.
- English defaults for English-page newsletter and preferred-reply language selectors.
- The latest tighter focus halo, 8px-inset backgrounds, and bottom title-divider fixes.

Informational feature/media cards remain articles. Gallery selection uses the existing buttons and `aria-pressed`. Links keep their real destinations; fields keep their names, required/min/max constraints, and current API routes. No sample card copy, invented gameplay imagery, store links or release dates were introduced.

## Source and build

`scripts/sync-approved-ui.mjs` extracts component-only CSS, excluding the catalog's global page layout. It preserves media queries, pseudo-elements and component sub-elements. Required fonts, textures, vector frames, license texts and the reusable script are vendored into `public/assets/ui/outpost/`, outside the folder regenerated by `copy-fonts.mjs`. Source CSS/JS and copied asset SHA-256 hashes are recorded in the vendored manifest.

The standard build synchronizes UI assets, fonts and content, then compiles the server. When the sibling canonical UI library is absent, the build retains the checked-in UI snapshot. There is no dependency on the local Godot installation at deployment time.

`templates/header.html` and `templates/footer.html` are the canonical shared shell. `sync-headers.mjs` expands the language options and synchronizes all five English pages. `sync-language-options.mjs` preserves the page locale as the selected form-language default.

The initial UI integration retained `site/`, API routes, mail transport, CSP and Azure workflows. The later localization work adds locale-aware page/404 routing, an optional `uiLocale` form value, and translated confirmation text. The user's existing public-directory discovery logic in `server/app.ts` remains intact.

- Privacy: `http://127.0.0.1:4180/en/privacy/`

The preview binds to `127.0.0.1`, removes SendGrid variables from its process, and uses the existing mock delivery path. It sets the app's non-listening environment before importing the server, then starts its own loopback listener; this does not invoke a test runner. Stop it with Ctrl+C. Production start behavior and configuration are unchanged.

Review hover, keyboard and click focus; open/close the mobile menu; select languages; inspect long dropdowns; change gallery crops; enter long form messages; inspect validation and submission statuses with mock delivery; and inspect narrow/desktop layouts and browser zoom. No automated tests were run at the user's request.

The production build completed locally. Desktop and narrow-screen rendering were visually inspected in the browser without submitting forms. Saved views: [homepage](ui-review/home-desktop.png), [press](ui-review/press-desktop.png), [mobile contact form](ui-review/contact-mobile.png).
